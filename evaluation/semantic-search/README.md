# Сравнение смыслового поиска

В разделе приложения **«Тест смыслового поиска»** лежат 48 синтетических документов без тематических подразделов. Категории, 36 запросов, оценки релевантности и результаты измерений находятся только здесь, вне поискового индекса. Полная таблица и все тексты: [dataset](../../docs/semantic-search-dataset.md). Интерактивная таблица: [report.html](report.html).

## Варианты

| Профиль | Векторы | Отбор результатов |
|---|---|---|
| `baseline` | Исходный текст без инструкций | Старый порог 0.25, отрыв лидера 0.04, до 5 источников |
| `prompted` | Google: `task: search result \| query:` / `title: none \| text:` | Лучший фрагмент каждого источника до ограничения кандидатов; без требования отрыва лидера; порог подбирается по dev |
| `reranked` | Те же векторы, что у `prompted` | Gemma оценивает кандидатов; совпадение общей темы не должно считаться ответом; после проверки до 5 источников |

Один код и одна ветка `codex/semantic-search-evaluation`; профили переключаются конфигурацией. Это сохраняет одинаковый API, корпус и обработку документов. У старого формата индексный ключ `embeddinggemma`, у нового `embeddinggemma|retrieval-v1`. Смена формата автоматически пересчитывает производные векторы. Между B и C пересчёт не нужен. Обычный подстрочный поиск базы знаний не использует эти профили.

Дополнительный диагностический замер `prompts-only`: профиль prompted, `RequireLead=true`, `DiversifySources=false`, порог 0.25. Он меняет только инструкции embedding-модели, сохраняя старый отбор. Такой замер отделяет эффект инструкций от изменений фильтров.

Инструкции: [Google EmbeddingGemma](https://ai.google.dev/gemma/docs/embeddinggemma/model_card#prompt-instructions). Формат ответа Gemma: [Ollama structured outputs](https://docs.ollama.com/capabilities/structured-outputs).

## Данные и безопасность повторного запуска

`benchmark.py seed` создаёт фиксированные UUID через обычный Knowledge API. Перед первым добавлением записывается manifest. Повторный запуск сверяет содержимое и пропускает существующие записи; при несовпадении останавливается без перезаписи. Корпус и разметка защищены SHA-256 из `fixture-lock.json`.

Файлы корпуса и запросов закреплены с окончаниями строк LF через `.gitattributes`: их SHA-256 вычисляется по байтам и совпадает после checkout на Windows и других системах.

Перед импортом сохранены отдельный `pg_dump` V2, исходная Knowledge JSON V1, Tasks JSON V1 и полный ответ Knowledge API V2. Состояние и резервные копии содержатся **вне репозитория**, на этой машине: `C:\Users\Vitaly\Documents\Codex\artifacts\semantic-search-20260927`. Manifest содержит хеши исходных узлов, GUID тестовых документов и временной интервал импорта. Рабочая синхронизация штатно переносит тестовый раздел в V1.

В текущем Search API нет фильтра раздела. Runner использует `kinds=knowledge.document` и интервал создания тестовых документов, затем обязательно сверяет полный набор выбранных источников PostgreSQL с manifest. Если в интервал попадёт чужая запись или тестовый документ изменится, измерение останавливается. Это оценка **только синтетического корпуса**, а не неразмеченного смешанного содержимого пользователя. Даты одинаковы для всех профилей и не передаются Gemma как подсказки.

Перед каждым запуском проверяются все 48 источников, актуальная версия каждого фрагмента, наличие векторов и соответствие индексного ключа активному профилю. Исходные узлы Knowledge должны оставаться неизменными. Приватные тексты не пишутся в файлы результатов.

## Измерения

- 24 dev-запроса используются для настройки; 12 test-запросов — для контрольного сравнения после фиксации параметров. Исходный baseline test был заранее записан в отдельный файл и не открывался при настройке.
- `scores` читает актуальные векторы и вычисляет оценки для **dev**, не вызывая test-запросы. Сетка абсолютного порога: 0.25…0.75 с шагом 0.02. Критерий выбора заранее задан: гармоническое среднее макро-точности реально выданных результатов и макро-полноты положительных запросов; при равенстве — nDCG, затем меньший порог.
- `recallAt5` — доля ожидаемых документов в первых пяти результатах, среднее по запросам с ответом. `ndcgAt5` учитывает оценки 2/1 и положение. `reciprocalRank` учитывает первый подходящий ответ.
- `precisionReturned` — доля подходящих среди фактически выданных, максимум пяти. Это **не** Precision@5. Пустой ответ получает точность 1 только у запросов без ответа; потеря доступности не засчитывается как правильное воздержание.
- `noAnswerCorrect` отдельно оценивает два запроса без ответа в каждой части. `hardNegatives` считает только заранее отмеченные сложные отрицательные документы; `falsePositives` — все лишние результаты.
- Время — один последовательный проход разных запросов, вместе с HTTP и подсветкой. Оно может включать холодную загрузку, прогрев и другие нагрузки, поэтому это наблюдаемые времена, а не надёжный нагрузочный benchmark.
- Fallback Gemma отмечается отдельно: при ошибке/таймауте показываются обычные векторные результаты с явной заметкой. Такие результаты нельзя приписывать успешной работе Gemma.

Первые прерванные диагностические C-запуски сохранены отдельно (`*-diagnostic-dev.json`) и не входят в финальное сравнение: сначала исправлена двойная сериализация кириллицы в тексте prompt, затем уменьшено число кандидатов на основании dev recall и задержки.

## Повторить

Требуются работающие Docker Compose V2, локальная Ollama и Python 3 (runner использует только стандартную библиотеку). Сначала сделать резервную копию. Для этой машины Python доступен по пути ниже; менять его можно на свой интерпретатор.

```powershell
$python = 'C:\Users\Vitaly\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe'
$state = 'C:\Users\Vitaly\Documents\Codex\artifacts\semantic-search-20260927\state.json'
& $python evaluation/semantic-search/benchmark.py seed --state $state
& ./evaluation/semantic-search/set-profile.ps1 -Profile prompted -MinimumSimilarity 0.41 -RequireLead false -DiversifySources true
& $python evaluation/semantic-search/benchmark.py run --label prompted --split dev --state $state --output evaluation/semantic-search/results/prompted-dev.json
& $python evaluation/semantic-search/benchmark.py scores --state $state --output evaluation/semantic-search/results/prompted-dev-scores.json
& $python -m unittest discover -s evaluation/semantic-search -p test_benchmark.py
```

`set-profile.ps1` пересоздаёт только контейнер приложения из уже собранного образа и ждёт готовности векторов; БД и содержимое документов сохраняются. Настройки этого скрипта временные для контейнера; постоянные значения задаются в Compose / V2 `.env`. Для C добавить `-Profile reranked -RerankCandidates 8`; для исходного A использовать `-Profile baseline -MinimumSimilarity 0.25 -RequireLead true -DiversifySources false`.

```powershell
& $python evaluation/semantic-search/report.py --runs evaluation/semantic-search/results/baseline.json evaluation/semantic-search/results/prompted.json evaluation/semantic-search/results/reranked.json
```

HTML автономный: содержит корпус, разметку и переданные результаты, фильтр по запросу/категории, выбор dev/test и раскрытие документов. Для браузера без доступа к локальным файлам можно временно обслуживать только эту папку через `python -m http.server 8769 --bind 127.0.0.1 --directory evaluation/semantic-search`.
